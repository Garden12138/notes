## 集群

### 数据分布

* 数据分布理论，分布式数据库的核心问题是如何将整个数据集按照分区规则映射到多个节点上，使每个节点负责整体数据的一个子集。常见的分区规则包括哈希分区和顺序分区。
  * 哈希分区：具有良好的离散性，数据分布与业务无关，但无法顺序访问。这是```Redis Cluster```采用的方式。
  * 顺序分区：数据分布与业务相关，支持顺序访问，但容易产生数据倾斜。

  针对哈希分区，书中介绍了三种常见的规则：

    * 节点取余分区：
      * 使用 ```hash(key) % N（N为节点数）```计算映射关系。
      * 优点：实现简单。
      * 缺点：当节点数量变化（扩容或收缩）时，映射关系需要重新计算，会导致大规模的数据迁移。通常建议采用翻倍扩容的方式以减少迁移量。

      ![](https://raw.githubusercontent.com/Garden12138/picbed-cloud/main/redis/redis_dev_maintenance_37.png)

    * 一致性哈希分区：
      * 为每个节点分配一个```Token```并构成一个哈希环（范围0~2 ^ 32-）。数据根据```key```的哈希值顺时针找到第一个大于等于该值的```Token```节点。
      * 优点：增减节点只影响邻近节点。
      * 缺点：节点较少时容易分布不均；增减节点会造成部分数据无法命中，更适合缓存场景。

      ![](https://raw.githubusercontent.com/Garden12138/picbed-cloud/main/redis/redis_dev_maintenance_38.png)

    * 虚拟槽分区：
      * 这是对一致性哈希的改进，它使用分散度良好的哈希函数将数据映射到一个固定范围的整数集合中，这些整数被称为槽（```slot```）。
      * 槽是集群内数据管理和迁移的基本单位。

      ![](https://raw.githubusercontent.com/Garden12138/picbed-cloud/main/redis/redis_dev_maintenance_39.png)

      ![](https://raw.githubusercontent.com/Garden12138/picbed-cloud/main/redis/redis_dev_maintenance_40.png)

* ```Redis```数据分区，```Redis Cluster```采用了虚拟槽分区，其特点如下：
  * 槽的范围：所有的键根据哈希函数映射到 0~16383 整数槽内。
  * 计算公式：```slot = CRC16(key) & 16383```。
  * 管理方式：每一个节点负责维护一部分槽以及槽所映射的键值数据。
  * 核心优势：
    * 解耦了数据和节点的关系，简化了节点扩容和收缩的难度。
    * 节点自身维护槽的映射关系，无需客户端或代理服务维护元数据。
    * 支持节点、槽、键之间的映射查询，便于数据路由和在线伸缩。

* 集群功能限制，由于```Redis Cluster```r是分布式架构，相比单机模式在功能上存在一些限制，开发人员需要规避这些“坑”：
  * ```Key```批量操作限制：如 ```mset```、```mget``` 等，目前只支持具有相同```slot```值的```key```执行批量操作。
  * 事务操作限制：只支持多```key```在同一节点上的事务操作，跨节点事务无法使用。
  * 数据粒度限制：```Key```是数据分区的最小粒度，不能将一个巨大的键值对象（如非常大的hash或list）映射到不同的节点。
  * 数据库空间限制：单机支持16个数据库，而集群模式下只能使用一个数据库空间，即 ```db0```。
  * 复制结构限制：复制结构只支持一层，即从节点只能复制主节点，不支持嵌套的树状复制结构。
