京东智推：
项目描述：该项目为京东营销云5G超信投放平台，包含信息管理、内容管理、效果报表、互动CRM、财务管理、账户中心以及系统设置等功能模块，为京东营销提供5G超信的精准投放能力。
项目职责：主要负责设计后端DDD开发模型框架，参与信息管理、内容管理和投放报表的核心业务开发，协助京东侧的技术人员进行测试环境、预发环境以及生产环境的部署。
项目挑战：系统功能模块多且涉及大量跨模块数据交互，传统单体/分层架构难以应对复杂业务逻辑的演进和快速迭代需求，落地领域驱动设计（DDD）架构，将业务划分为多个独立领域和限界上下文，配合CQRS和事件驱动机制实现模块解耦，提高业务扩展性与可维护性。

项目挑战：历史数据权限规则与新权限模型存在结构性差异，需要制定安全高效的迁移策略，避免数据错配和访问控制漏洞，通过设计双写机制与灰度发布方案，在新旧权限体系并行运行阶段确保数据同步一致，并逐步切换到新体系，降低迁移风险。

统一短信平台
项目描述：为博今集团构建的企业级短信营销平台，支持多企业用户使用，提供短信模板管理、智能发送控制、实时状态跟踪、数据统计分析等核心功能。平台具备强大的业务编排能力，支持自定义发送策略、多通道商智能路由、批量短信处理、回执状态管理等功能，通过统一接口实现短信的快速发送和状态回传，为企业提供完整的短信营销解决方案，显著提升了营销效率和用户体验。
项目职责：负责整体架构设计，定义消息及其流向，设计并实现关键组件如白/黑名单、频控、模板/参数统一、默认策略等前置校验组件，设计"策略链(Filter)"式业务编排，实现strategy_optimize、tpl-one2many等链式可插拔策略，封装http、cmpp等通道商接口，实现智能路由和负载均衡，实现消息标识映射、延时重试、长短信聚合、回执补发、去重幂等回执处理组件。
项目挑战：
1、入口高并发与快速响应：开放网关仅做鉴权与校验后“快速入 Kafka（sms_receive_topic）”，后端异步处理；对外秒级响应，内部消费弹性扩容。
2、多协议/多通道统一（HTTP/CMPP/测试）：适配器模式抽象发送与回执；通道元数据驱动参数映射与签名封装；统一结果模型；错误码与重试策略统一。
3、回执与发送数据关联难（跨系统、不同时序）：sendMsgId + channelType + phone 为 Redis Key 建立映射；sms-rpt-handler-first 获取失败走 kafka-delay 多次补取；最终兜底 DB 查询。
4、长短信分片聚合与成功判定：片段聚合表/Redis 记录片段到齐度；至少一片成功即判成功策略；不全则告警与补偿。
5、频控与黑白名单在高并发下的一致性/性能：名单/频控规则本地缓存+Redis 原子计数；规则热更新；热点业务限流与快速失败就地回执（expectType=notify_failed）。
6、策略链扩展性与可观测性：策略元数据中心（sms_strategy_handler）+链式执行器；链路埋点、每节点耗时/命中/失败率监控；灰度与熔断开关。
7、批量入库与数据链路分层：发送/接收/通知分表（send_his/receive_his/notify）；Kafka 批消费+批插；冷热分层与必要索引；大数据侧 bigdata_* 主题同步。
8、定制客户的差异化适配（京准通/钉钉）：common-adapter-sdk 统一适配层，将定制报文映射为平台标准模型，保持主链路零侵入。
9、CMPP 对客与供应商侧协同：cmpp-server 对客收发、sms-provider-cmpp 供应商侧；状态机式回执流转，异常场景专项回归与压测。
10、全链路监控与告警：Kafka 堆积、消费延迟、通道成功率、模板命中率、回执丢失率等指标看板；异常自动告警（无法处理回执邮件/IM）。

项目挑战：开源版本Python版本兼容性问题，深入分析各依赖库的版本兼容性矩阵，选定稳定版本，对不兼容部分实现重构。

AI数据分析服务
项目描述：基于Dify开源框架构建的智能数据分析工作流平台，通过可视化流程编排实现SQL查询、数据清洗、图表生成、智能分析等全链路数据处理。平台支持多种图表类型（线性图、柱状图、饼图）的自动生成和智能分类，集成DeepSeek-V3等大语言模型，实现自然语言到SQL的转换和数据分析结果的智能解读，为企业提供高效的数据洞察解决方案。
项目职责：负责Dify平台本地化部署，主导AI工作流编排设计。
项目挑战：部署嵌入模型时需运行Ollama服务，但Ollama服务在Linux部署复杂，模型下载和管理困难，通过本地上传模型以及使用systemd管理服务，实现模型的快速部署和管理；数据库表知识库召回测试成功率不高，通过优化创建知识库的文本内容，控制数据库表段落的大小，提升召回准确率。

OCR识别营业执照信息服务
项目描述：基于开源OCR模型构建的企业级文字识别服务，为博今集团提供高精度的图片文字提取能力。服务支持多种翻转的图片，能够实现智能识别提取文字，提供RESTful API接口供各业务系统调用，提升了业务系统的识别效率和准确性。
项目职责：主导图片矫正模型、OCR模型的调研与效果评估，负责图片文字识别服务的开发与部署。
项目挑战：OCR模型多且参数大，部署困难，对OCR模型进行INT8/FP16量化，将模型大小减少50-70%，显著降低内存占用，进行模型剪枝，移除冗余参数和层，在保持准确率的前提下进一步压缩模型体积；Transformers推理速度慢，响应时间长，将推理方式从Transformers切换到vLLM，利用其优化的推理算法和内存管理，将响应时间从30s降低到2s。
