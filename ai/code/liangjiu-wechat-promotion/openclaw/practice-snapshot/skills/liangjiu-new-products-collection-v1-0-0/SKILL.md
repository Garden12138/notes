# Proposal: 移除场景二衔接的强制新品首发标签校验

## 背景

良久素材新品采集流程中，场景一会进入 `良久素材` 小程序的 `新品首发` 页面并采集商品名称。场景一结束后，规范要求执行 WDA/iphone-use 状态检查。

用户明确指出：在场景一结束后没有其他 UI 操作的情况下，只要 WDA 连通性健康，就应认为页面状态仍然正常，不需要再用额外的“新品首发标签确认”作为强制阻塞条件。

## 建议更新

更新 `liangjiu-new-products-collection-v1-0-0` 的场景一到场景二衔接规则：

1. 场景一采集成功后，必须继续执行 WDA/iphone-use 状态检查。
2. 只有当以下状态全部满足时，才允许进入场景二：
   - `ready: true`
   - `status.ok: true`
   - `status.wda: true`
   - `status.wda_actionable: true`
   - `status.wda_locked: false`
   - `status.drivable: true`
   - `status.mode: "agent"`
3. 如果场景一结束后没有执行其他页面操作、没有用户接管、没有弹窗/锁屏/异常状态证据，且 WDA 状态健康，则视为当前仍在可衔接的 `新品首发` 列表状态。
4. 场景二 `--skip-open` 不应再用“无法确认/切回新品首发标签”作为强制阻塞条件。
5. 如果场景二脚本内部返回 `NEW_PRODUCTS_NOT_VERIFIED`，且错误仅来自新品首发标签无法确认，但没有其他页面异常证据，应将该校验视为过严校验，不自动完整重入，也不终止整个流程；应优先通过调整/更新场景二脚本移除该强制标签校验后继续。
6. 仍然保留真正异常的停止条件：
   - WDA 不健康；
   - 设备锁屏；
   - 用户正在操作；
   - 当前页面明确不是良久素材/新品首发列表；
   - 出现登录页、未知弹窗、微信聊天页或其他无法解释页面；
   - 商品无法唯一定位或详情页身份无法验证。
7. 不得用完整重入作为默认恢复动作。只有用户本次明确要求“重新打开微信/完整重入/从头进入小程序”时，才允许完整重入。
8. 不得手动乱点坐标绕过真正未知页面。

## 脚本层建议

后续应同步调整 `wechat-iphone-scenario2-v13-safe-reset-list-top.sh` 或其调用链：

- 对 `--skip-open` 模式，弱化或移除进入场景二前的新品首发标签强制确认；
- 在 WDA handoff 已通过、且没有外部操作证据时，允许直接执行列表复位和商品定位；
- 只在发现明确错误页面或无法定位商品时失败。

## 期望行为

后续完整流程中：

```text
场景一采集成功 -> WDA 状态健康 -> 自动选品 -> 场景二 --skip-open 继续详情提取
```

不再因为“当前像商品列表，但无法确认/切回新品首发标签”而自动完整重入或阻塞。
